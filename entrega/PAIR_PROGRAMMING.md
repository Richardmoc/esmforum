# Planejamento de pair programming

Trabalho individual: este documento descreve como eu aplicaria a prática **se tivesse um par**. Não houve sessão de pair programming entre dois alunos neste atendimento.

Usaria VS Code Live Share para edição compartilhada e uma chamada de voz com compartilhamento de tela. A cada 20–25 minutos, alternaria driver e navigator. O driver escreve e executa o código; o navigator acompanha os critérios de aceite, identifica casos-limite e questiona decisões. Ambos permanecem envolvidos; dividir frontend e backend e trabalhar separadamente não caracteriza pair programming.

Sessão proposta de 90 minutos: 10 minutos para critérios; 25 para o serviço e testes; 25 para repositório SQLite e integração HTTP; 20 para interface; 10 para revisão e registro das decisões. A rotação ocorre mesmo que a tarefa não tenha terminado.

Foco da revisão: termo vazio, limite de tamanho, busca literal, SQL parametrizado, erros de rede e preservação das rotas existentes. Ao final, registraríamos participantes, decisões, testes e dúvidas reais. Nenhuma evidência de sessão ou participação foi inventada.
